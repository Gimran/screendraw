## Обязательное правило скриншотов

Пользователь работает параллельно. Для КАЖДОГО снимка экрана/окна, который агент делает для проверки:
1. Сначала оранжевое предупреждение сверху по центру, звук и обратный отсчёт; дождаться окончания.
2. Только после предупреждения запускать/показывать снимаемое окно.
3. Пауза 1–2 секунды и сразу снимок.

Предпочтительная команда (порядок зашит в скрипт):
`pwsh -NoProfile -File "$env:USERPROFILE\.Codex\scripts\take-screenshot.ps1" -Out <файл.png> [-Launch "<команда>"] [-Settle 2] [-Seconds 3] [-Crop x,y,w,h]`

При другом способе съёмки сначала:
`pwsh -NoProfile -File "$env:USERPROFILE\.Codex\scripts\screenshot-warn.ps1" -Seconds 3`
и лишь затем запуск/показ окна и снимок. Если скрипта нет — не снимать экран молча.

## Приложение

C# / WPF, Windows x64, .NET 10. Независимая утилита скриншотов по образцу Яндекс.Скриншота, без облачной зависимости. Подробности: README.ru.md и README.md.

- Трей, горячая клавиша Ctrl+Shift+` (обратная кавычка), выделение области, несколько мониторов/DPI.
- Тёмный редактор; обычное окно, не Topmost. Только захват экрана поверх окон.
- Стрелки (обычная, сужающаяся, пунктирная с изгибом), линии, рамки, овалы, текст, выноски, маркер, пикселизация, обрезка.
- Объект после рисования выделен, инструмент остаётся активным; пустая область начинает новую фигуру.
- Рамки Corel: размер без принудительного сохранения пропорций, поворот вокруг перемещаемой точки. Стрелки/линии/маркер — узлы вместо рамки.
- Текст: светлый/тёмный фон либо без фона, масштабирование рамкой.
- Выноски: размер рамкой плюс узел указателя. Рисование можно начинать во всей рабочей области вне изображения; холст расширяется.
- Zoom: Ctrl+колесо и нижний ползунок; панорама средней кнопкой мыши.
- Вставка изображений, удаление цветового фона, прозрачный PNG и буфер обмена.
- Две основные строки панели: инструменты, опции. Действия сохранения/копирования внизу.
- Копирование всегда также сохраняет файл. Закрытие после успешного сохранения/копирования включено по умолчанию.
- Русская и английская локализация в Loc.cs.
- Пользователь отказался от интеграции «поделиться» через Google Drive API: не добавлять её без нового запроса.
- Иконка app_new.ico — актуальная, исходный файл используется как ресурс для всех окон и трея и как ApplicationIcon.

## Последняя правка и проверка

SaveLocation.cs:
- Проверяет непустой абсолютный путь и доступность корня диска/сетевого ресурса.
- Создаёт отсутствующие вложенные папки.
- При ошибке записи вызывает выбор другой папки и повторяет операцию; при отмене возвращает отсутствие результата.

EditorWindow.cs:
- Save, Copy, CopyPath используют общую обработку папки.
- При ошибке пользователь видит сообщение и предложение выбрать другую папку.
- При отмене редактор остаётся открытым, без ложного сообщения об успехе.
- Новая папка запоминается после успешной операции.
- Ошибка буфера также не закрывает редактор и не затирается сообщением об успехе.
- Имена новых файлов содержат доли секунды для уменьшения риска совпадений.

Тесты: `tests/SaveLocation.Tests.csproj`, запуск:
`dotnet run --project tests/SaveLocation.Tests.csproj -c Release`

12 автоматических тестов прошли: создание папки, существующая папка, null/пустой/относительный/некорректный путь, файл вместо папки, отсутствующий диск, отказ в записи (инъекция исключения), реальная блокировка выходного файла, исчезновение папки перед записью, распространение не-файловой ошибки. Проверена логика восстановления; диалоги мышью не проверялись. Тесты работают только в собственной временной папке.

## Сборка и известная проблема окружения

Обычная команда:
`dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o dist`

В старом чате sandbox writable_roots всё ещё указывали на H:, поэтому операции в D: выполнялись через require_escalated. Эти запросы разрешения прошли. Это не означает, что у Windows или пользователя нет доступа к папке D:.

При сборке непосредственно в D: возникала отдельная ошибка CreateAppHost / MSB4018: «Запрошенную операцию нельзя выполнить для файла с открытой пользователем сопоставленной секцией». Причина НЕ установлена; не утверждать, что виноват Google Drive, антивирус или права доступа.

Рабочий обход, уже проверен:
1. Создать уникальную папку в %TEMP%.
2. Скопировать туда корневые *.cs, *.csproj, *.ico, *.manifest, Assets и исходники tests (без bin/obj).
3. Запустить тесты и publish в этой временной папке.
4. Обновить dist готовыми ScreenDraw.exe и ScreenDraw.pdb, предварительно безопасно закрыв только экземпляр приложения из этого проекта.
5. Запустить dist\ScreenDraw.exe в трее.

Сборка прошла с существующим warning CS0067 (CanvasView.ToolChanged не используется). Последняя сборка запущена из актуального dist. Новые GitHub Releases в последних двух задачах не публиковались; не считать старый релиз актуальной сборкой.
